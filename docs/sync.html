Sync optional · git-based · offline-first

Sync is never required. Everything works with Wi-Fi off. When you want a second machine — or history with teeth — share ~/devnote through a private git repo.

On this page · Setup · How it works · Conflicts · Status dot · Backup

Setup in 3 steps

1
Create a private repo, e.g. git@github.com:you/devnote.git.
2
In devnote: Preferences → General → Git sync, paste the remote URL.
3
Click Sync now — initializes the repo, exports notes, commits, pushes.

How it works

  • Each note is one .md file with YAML frontmatter: ~/devnote/<notebook-path>/<slug>-<id8>.md.
  • Sync now = export → commit → pull → resolve conflicts → push → import.
  • Manual trigger only — you control when to sync. No background uploads, no surprises.

Conflicts

Never silently drop text. Per-file granularity: newer updatedAt wins, the loser is preserved as <name>.conflict-<device>.md plus a banner.

Deleting a note sets trashed: true in frontmatter (a tombstone), so deletes propagate across machines without resurrecting files. Permanent delete prunes the file.

Status dot

DotMeaning
● greenSynced — everything committed & pushed.
● yellowUncommitted local changes.
● blueCommitted, unpushed.
● redConflict — resolve the .conflict-* file, then sync again.

Backup & restore

Preferences → General → Backup & restore → Export backup creates ~/devnote-backup-YYYY-MM-DD.zip with all notes. Restore overwrites ~/devnote from a zip. Your user-data dir location is documented in the same panel.

iOS path: sync via Working Copy (manual git client) — documented in the roadmap. E2EE via git-crypt/age is a planned later layer.
